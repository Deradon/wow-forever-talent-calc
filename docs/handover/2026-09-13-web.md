# Handover: web app M1 (2026-09-13)

Workstream C, `docs/briefs/web-app.md`, milestone M1. Everything below lives
in `web/` and `.github/workflows/`; nothing under `data/` or `pipeline/` was
touched.

## What exists

- `web/` scaffolded with `npm create vite@latest -- --template react-ts`
  (create-vite 9.2.1). Installed: vite 8.3.0, react 19.3.0, typescript 6.0.3
  (template pin `~6.0.2` kept), @vitejs/plugin-react 6.1.1, tailwindcss +
  @tailwindcss/vite 4.3.3, zod 4.6.3, @floating-ui/react 0.27.20, vitest
  5.0.0, fast-check 4.10.0, @playwright/test 1.63.0, oxlint 1.82.0. Every pin
  in the brief installed as given; no substitutions.
- `src/data/schema.ts`: Zod mirror of `docs/DATA-SCHEMA.md` (`looseObject`
  everywhere so unknown keys pass through; `requires` is an array of 1..3;
  `maxRank` capped at 9; page ids `primary|secondary` to match the JSON
  Schema's enum). `renderDescription(talent, r)` fills `{n}` slots.
- `src/data/load.ts`: `import.meta.glob` over `data/talents/*.json` (always,
  lazy) plus `data/examples/*.json` and `web/tests/fixtures/*.json` when
  `VITE_INCLUDE_EXAMPLES=1`. Precedence per class id: talents > examples >
  fixtures. `.env.development` and `.env.e2e` set the flag; the deploy
  workflow sets it too until the first real class exists (remove it then).
- `src/data/encoding.ts`: registry of `data/encoding/v*.json` and
  `data/encoding/migrations/*.json` (eager glob) plus fixture encodings under
  the same flag (never overriding a real version). `orderFor()` falls back to
  the class file's own order (pages flattened, row-major) when a class is not
  listed for its current `dataVersion`, so unpublished classes still get links.
- `src/rules/`: pure engine per brief section 3/4 (`points`, `level`,
  `validate`, `mutate` with `canAdd/canRemove/add/remove/validate/sanitize/
  resetTree/resetAll`). Reasons: `maxed no-points page-full row-locked prereq
  would-orphan not-spent unknown-talent`. `canRemove` simulates and compares
  violations before/after. `rules.pointsPerPage`, when present, is an extra
  per-page cap on top of `maxPoints` (see open questions).
- `src/url/codec.ts` (`encode/decode`, notices `unknown-version clamped
  unknown-talent adjusted bad-string`), `src/url/route.ts` (hash routing
  `#/`, `#/<class>?v=&t=`, `#/review/<class>`).
- `src/ui/`: `ClassPicker`, `ClassPage` (URL is the source of truth on
  arrival; edits go to state and `history.replaceState`), `PageTabs` (only
  when >1 page, shows per-page counts and budgets), `TreePanel` (CSS grid,
  44px cells, 12px gap), `Arrows` (SVG polylines, straight or L-shaped, gold
  when satisfied), `TalentCell` (four states via `data-state`, left click add,
  right click / Backspace remove, initials fallback while no icons exist),
  `Tooltip` (name, Rank x/y, current text, "Next rank:", red requirement
  line, caveat when `ranksSource != observed`, provenance line), `Header`
  (points left, required level, per-tree counts, Reset, Copy link), `Notice`
  ("Build adjusted" and other decode notices), `ReviewPage` (M2 stub),
  `talents.css` (the skin).
- `tests/fixtures/tinker.json` (section 11 example, `dataVersion` 1 to match
  `data/examples/tinker.json`) and `tests/fixtures/encoding/v1.json`.
- `tests/smoke.spec.ts` + `playwright.config.ts` (`webServer: npm run
  build:e2e && npm run preview`, port 4173, clipboard permissions).
- `.github/workflows/deploy.yml` per brief section 2 (checkout v7,
  setup-node v7, configure-pages v6, upload-pages-artifact v5, deploy-pages
  v5; `VITE_BASE=/<repo>/`).
- `web/README.md` with the commands.

## Deviations from the brief

- Example classes and fixture encodings are part of the app behind
  `VITE_INCLUDE_EXAMPLES`; the deploy workflow sets it so Pages is not empty
  before the first real class. Remove that env line once `data/talents/` has
  a file.
- `rules.pointsPerPage` is enforced (per-page cap in addition to `maxPoints`)
  rather than ignored, because the example class ships it.
- A `bad-string` notice exists for non-digit build strings (not in the brief).
- `orderFor` falls back to the class file's order when the encoding file does
  not list the class (brief assumes it always does).

## M2 (2026-09-13, second session)

Scope: `web/` only. First real class (`data/talents/paladin.json`, 45
talents, all `iconSource: "crop"`) is live; the deploy workflow no longer sets
`VITE_INCLUDE_EXAMPLES` (only a stale comment remains in
`.github/workflows/deploy.yml`, outside this workstream).

### What changed

- **Crop icons.** `src/data/crops.ts` globs `data/review/*/*/*.png` eagerly
  with `{ query: '?url', import: 'default' }` and maps repo-relative paths
  (`iconCrop`, `source.crop`, both as the schema spells them) to asset URLs.
  Eager was chosen because the glob yields URL strings only (about 60 bytes
  per crop; nine classes add roughly 60 kB to the bundle) while lazy would
  have produced one micro-chunk per PNG. `vite.config.ts` sets
  `build.assetsInlineLimit` to a function that refuses to base64-inline
  anything under `data/review/` (the 36 px icons are about 4 kB, right at
  Vite's default inline limit). `TalentCell` renders `iconCrop` for
  `iconSource: "crop"`, `public/icons/<icon>.jpg` otherwise, initials when
  the file is missing or fails to load; `data-icon="crop|file|initials"` on
  the cell for tests. `.cell img` has `image-rendering: auto`.
- **Class picker.** One card per class: `className`, tree names with talent
  counts, total talents, data source, reviewed count, link to the review
  queue with its size. Note about BlizzCon 2026 footage / unreviewed /
  assumed rules and a link to the GitHub repo; footer now names the repo
  and says "not affiliated with or endorsed by".
- **Review route** `#/review/<class>` (`src/ui/ReviewPage.tsx`, ordering in
  `src/ui/review.ts`, unit tested): unreviewed below 80% first, then other
  unreviewed, then reviewed; confidence ascending within, then tree order,
  row, col. Each row: tooltip crop (300 px wide), icon crop at cell size,
  name/id, tree/row/col/maxRank, confidence + reader, `ranksSource` +
  observed ranks + `ranksNote`, stream timestamp/frame/video, `source.note`,
  `source.readings`, `requires`; then `TooltipContent` at rank 1 and at max
  rank. Read-only. Header line with totals.
- **Titles.** `useTitle` hook (`src/ui/title.ts`): picker "WoW Forever
  Talent Calculator", class page `"<Class> h/p/r - WoW Forever Talent
  Calculator"` (per-tree points in file order, live), review page
  `"Review <Class> - ..."`.
- **`ranksSource: "manual"`.** Tooltip never shows the rank-1 placeholder
  copies as real text: "Next rank:" block says "Higher ranks unknown (only
  rank 1 was read)", a rank beyond the observed ones shows the highest
  observed text plus "Rank N values unknown", caveat reads "Ranks 2+
  unknown: <ranksNote>".
- Tests: `src/data/crops.test.ts` (every `iconCrop`/`source.crop` in
  `data/talents/` resolves; fails if a class points at an unshipped crop),
  `src/ui/review.test.ts` (ordering), `tests/paladin.spec.ts` (picker card,
  crop icons decode, title updates, manual tooltip, review route).
- `web/README.md`: routes and an "Icons and crops" section.
