## 1. The Classic Era diff (idea 3)

`web/scripts/gen-data-index.mjs` gained a third output,
`web/src/data/classic-diff.json`, built from `data/talents/*.json` against
`data/prior/classic-era/talents.json`. It runs in the same vite plugin as the
other two indexes, so every dev server, build and vitest run refreshes it, and
`src/data/classicDiff.test.ts` fails when a commit forgets to.

**Matching.** Names are the only stable join (talent ids were re-slugged), so
`normalizeName` folds case, apostrophes and punctuation, and matching is
**exclusive and two-pass**: same tree first, then anywhere in the class. That is
what keeps a talent that changed tree a `moved` rather than a `new` plus a
phantom removal.

**Classification**, worst news first: `new` (no counterpart) > `moved` (tree,
row or column differs) > `rank-changed` (same cell, different `maxRank`) >
`same`. A talent that both moved and changed rank count reports the move,
because the cell is what the player is looking at; the prior record carries the
old rank count either way.

Today: **145 new, 132 moved, 18 re-ranked, 174 unchanged, 108 Classic talents
gone** across the nine classes (the brief's estimate was 146/131/18/174/109).
Warrior gains Bloodthrill, Weaponmaster, Focused Rage and loses the four weapon
specialisations, as predicted. `removed[]` is written for the later `#/changes`
page and is not read by the calculator yet.

**Shape.** `same` entries are *omitted*: a missing entry in a class that has a
diff means unchanged, and a class with no prior at all (the tinker example)
reports `undefined`, so an example class never claims all its talents are new.
The file is 72 kB raw, ~6.6 kB gzip, of which ~2.4 kB is `removed[]`. If the
class route ever needs that back, split `removed[]` into its own generated file.

**UI.** `src/ui/classicDiff.ts` is the read side. A 14px blue star sits in the
cell's top-right; `changeLine` in `tooltipText.ts` produces the single tooltip
line (`New in Forever.` / `Moved from row 3.` / `Moved from Arms, row 3.` /
`Now 3 ranks, was 5.`), rendered as `.changed` inside the card rather than
appended after it, so A1's line budget still holds.

**The switch** lives in the tree panel header (the class-page header belongs to
round 1a), rendered only by the leftmost panel of the active page, with its
state in `src/ui/highlightNew.ts` - a module-level store read through
`useSyncExternalStore`, so all three trees follow one switch without
`ClassPage` knowing. Deliberately not persisted and not in the URL: it is a way
of looking at a tree, not part of the build. On: unchanged cells drop to 0.28
opacity, changed cells get a blue ring. A talent the player has actually spent
points in is **never** dimmed.

## 2. Modifier clicks (idea 4)

Shift-click maxes, Ctrl- or Alt-click clears, right click still refunds one,
Shift-Backspace clears from the keyboard (Shift-Enter maxes for free, because a
keyboard-activated button click carries the modifier). `metaKey` is left alone:
cmd-click is the browser's gesture.

The interesting part is that this **cannot be a loop**. `onAdd` / `onRemove` are
the class page's handlers and each commits exactly one point, so a synchronous
loop would see the same stale `Build` five times and add one point. `TreePanel`
therefore holds a `Repeat` record and advances it **one point per render**
(effect on `[repeat, build]`), re-asking `canAdd` / `canRemove` each time and
stopping the moment a verdict refuses. No path bypasses the rules, and a
gesture that cannot start at all falls through to the single handler so round
1a's blocked-action message explains the refusal instead of nothing happening.
A `REPEAT_CAP` of 64 renders is the safety net.

Hold-to-repeat was in the brief as optional and was **not** built.

**One thing to settle with round 1a.** Because the repeat commits once per
point, a shift-click that fills a 5-rank talent pushes five entries onto round
1a's undo stack, so Ctrl+Z walks back one point at a time. If a single undo
should reverse the whole gesture, the repeat has to tell the history layer
where a gesture began and ended - `TreePanel.runRepeat` is the one place that
knows.

## 3. Tier gutter, arrows, locked cells (idea 6)

- `TierGutter` in `TreePanel.tsx` renders a 28px column left of the grid with
  `pointsPerRow * row` per row: dim once the row is paid for, **gold on the
  first row that is still locked**, blank on row 0. It mirrors the grid's own
  track sizing (`--cell` rows, `--gap`, the same 14px top padding), which is
  why it lines up without magic offsets - a Playwright case asserts the row
  centres agree to within 3px.
- `Arrows.tsx`: `markerWidth` 7 -> 4, `refX` 8 so the tip sits on the line's
  end, and the line stops `CLEARANCE` (5px) short of the target, inside the
  12px gap. Unsatisfied arrows are now dashed `#5a5f70`, satisfied solid gold -
  dashed carries the state without relying on colour. The **same-row** case is a
  real bug fix (usability finding 18): the old code turned upwards at the target
  column and drew the head straight across the target's icon; it now comes in
  from the side.
- Locked icons go to `grayscale(.75) brightness(.72)`. The rule lives in
  `cells.css` under `.tree-grid .cell[...]`, one step more specific than the
  base rule in `talents.css`, so it wins whatever order the sheets load in -
  `talents.css` belongs to round 1a and was not edited.

**Three marker slots, and they cannot collide**: `?` top-left, new-in-Forever
star top-right, rank badge bottom-right (22x22). On a 44px cell that leaves 8px
of clearance on the right edge; a Playwright case compares the two boxes.

## 4. Verification

`cd web && npx vitest run && npm run build && npx playwright test`.

New unit tests: `src/data/classicDiff.test.ts` (22 cases - normalisation,
classification precedence, exclusive and same-tree-first matching, the removed
list, the generated file's freshness and totals, and the accessor's three
answers: a status, `same`, or nothing at all) and a `changeLine` block in
`tooltipText.test.ts`. New Playwright file `tests/changes.spec.ts` (7 cases):
shift-click max, ctrl/alt clear, shift-click refusing at a locked row,
Shift-Backspace, the marker plus tooltip line for new/moved/unchanged, the
switch across all three trees, the tier gutter, and the arrow's dash and
z-order.

Checked visually at 1440x900 (`#/paladin`, five points in Holy, switch on):
gutter aligned with gold on the 10-point row, stars only on new talents,
`?` and star side by side on `infusion-of-light` without touching, locked rows
legible. Screenshot in the session scratchpad, not committed.

Main chunk after this work: 375.8 kB raw / ~115.6 kB gzip, which includes round
1a's parallel work; the diff's own share is ~5 kB gzip.
