## How to run

```
cd pipeline && uv run python validate.py ../data/examples/tinker.json --report
cd pipeline && uv run python validate.py ../data/talents/*.json --check      # CI
cd pipeline && uv run python validate.py ../data/overrides/warrior.json --overrides
cd pipeline && uv run pytest
uvx --with jsonschema python pipeline/validate.py data/examples/tinker.json  # without the project
python3 data/prior/classic-era/build.py                                       # rebuild the prior
```

Output: `LEVEL CODE file:class/tree/talent: message`, one summary line per
file, exit 1 on errors. Codes are `R<nn>-<TOPIC>` for the numbered rules
plus the named ones from the doc (`NEEDS-REVIEW`, `NONLINEAR-RANKS`,
`NEW-TALENT`, `MAXRANK-DIFFERS-FROM-CLASSIC`) and `UNKNOWN-CLASS`,
`PRIOR-UNKNOWN`, `PRIOR-SPELLS`, `ENCODING-ORDER`, `MANUAL-UNREVIEWED`,
`OVR-*`. `--json` gives `{ok, files[{file, errors, warnings, info, findings[],
reviewQueue[]}]}`; `reviewQueue` is what section 7 step 2 asks for (unreviewed
talents with confidence < 0.8, `ranksSource: manual`, `iconSource: crop`, or a
content warning), sorted by ascending confidence.

Current result on the example: 0 errors, 6 warnings (`UNKNOWN-CLASS`,
`R18-TREE-TOO-SMALL` x2, `R19-EMPTY-ROWS` x2, `NEEDS-REVIEW`); all inherent
to a fictional two-talent-per-row example. `--strict` therefore fails on it by
design.

takedown plan in `SOURCES.md`.

## Deviations from DATA-SCHEMA.md (doc updated where noted)

1. **Class id is a slug, not an enum** (doc section 3 updated). The schema
   accepts any slug; `validate.py` warns `UNKNOWN-CLASS` outside the nine
   known classes. Reason: the normative example uses class `tinker`.
2. **Example `dataVersion` 2 -> 1** (doc updated): only `v1.json` exists and
   rule 11 requires the file's version to be the highest present.
3. **Example `ranksPrior.classicSpellIds` for talent 1341** replaced with the
   real ids `[19407, 19412, 19413, 19414, 19415]` (doc and example) so the
   new `PRIOR-SPELLS` cross-check passes.
4. **Key order of `capstone`** in the `overclock` example fixed to the
   section 4.4 order (doc updated); the committed example is written through
   `canonical_dumps`.
5. **Serializer details** added to section 2: arrays of scalars (and of
   scalar arrays) are inline when they fit in 100 chars, everything else
   expanded, 2-space indent, trailing newline. Rule 12 `--check` compares
   against this serializer rather than a not-yet-existing `export.py`; export.py
   must import `canonical_dumps` from `validate.py`.
6. **Rule 12 without `--check`** reports a non-canonical `talents/` file as a
   warning, with `--check` as an error (doc updated).
7. **Rule 15** uses `rapidfuzz.fuzz.token_ratio` when the package is
   importable (it is in the uv project) and a difflib approximation
   otherwise, so the script stays runnable with `uvx --with jsonschema`.
8. **Rules 13 and 18 use the page budget**: when `rules.pointsPerPage` has an
   entry for the tree's page, that budget (capped at `maxPoints`) is used
   instead of `maxPoints`. Otherwise a 10-point secondary tree would always
   warn against 51.
9. **Overrides validation** derives its schema from the class schema's
   `$defs` inside `validate.py` (no separate schema file); `set` is a partial
   talent, `add` a full one, exactly one action per entry. The `if`
   conditionals in the class schema got `required` guards so partial objects
   do not trigger them.
10. `icon` for `iconSource: "crop"` must be exactly `crop-<talent-id>`
    (rule 9 in the validator; the doc says "provisional slug crop-<talent-id>").
11. `--no-files` and `--root` options (doc section 10 mentions them now).
12. Not implemented: rule 12's `REVIEWED-DIFF` (that is export.py's job) and
    an `export.py` itself.
