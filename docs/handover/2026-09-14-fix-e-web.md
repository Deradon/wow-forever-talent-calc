## E1 — a malformed `t=` is one sentence, not three developer bars

`web/src/url/codec.ts`. `Notice` keeps `message` (engineering prose), and gains
`count` (points, or talents capped) and `detail` (slugs, encoding positions,
rule reasons). A new pure `summarizeNotices(notices)` folds them into one
`DecodeSummary`:

- unreadable (`bad-string`, `unknown-version`) → *"This link could not be read;
  showing an empty build."*
- anything else → *"This link did not fit the current trees: 11 points were
  dropped and 12 talents capped at their Forever rank. The build below is what
  fits."*

`web/src/ui/Notice.tsx` renders exactly one bar with no bold title repeating its
own body, and `console.info`s the detail once per link. The three-bar case from
the review (`#/warrior?v=1&t=5553253055532530555325305553`) is a Playwright test.

Codec fuzzing with fast-check (`codec.test.ts`): random strings, digit/dash
strings, and a fixture list of real paste shapes (a Wowhead code, 5,000 nines,
`<script>`, `%2F..%2F`) crossed with `NaN`/`Infinity`/`1.5`/negative versions.
Every decode must yield a build that `validate` accepts, a summary that ends in
a full stop and contains no slug, position or engineering word, and a build that
re-encodes and re-decodes to itself.

## E2 — the print view

`web/src/ui/print.css`. The fix that mattered was re-pointing the **palette
tokens** inside `@media print` (`:root:root { --gold: #000; --text-dim: #333;
… }`) rather than chasing selectors: every colour in the app is a token or a
Tailwind arbitrary value reading one (`text-[var(--text-dim)]`), which is why
the previous per-selector approach kept missing the points line, the required
level, the rank column and the build URL. `:root:root` and not `:root` because
print.css is `@import`ed before the tokens are declared.

Also: `.tree-grid` and `.tree-body` forced to white with `background-image:
none` (the three panels printed as black rectangles), `svg.arrows polyline` and
its marker to `#333`, `.new-flag` and `.changed-flag` hidden (neither has a
legend on paper), highlight rings and the hover outline off, the `?` kept but as
ink, `.summary-head::after` (the build URL) at body size in black, and the
summary in two columns. Verified with `page.emulateMedia({ media: 'print' })`
screenshots of the production build before and after, and asserted in
`tests/round3.spec.ts` (backgrounds light, four text colours dark, markers
hidden, `columnCount === '2'`, URL ≥ 10 px and dark).

## E3/E4 — the import report and the import dialog

`web/src/url/import.ts`. `UnplacedTalent` is now one row per talent, not one per
lost point: `{ name, requested, kept, maxRank?, reason }` where `reason` is
`not-in-forever | fewer-ranks | rules`. `mapClassicBuild` caps the target at
`maxRank` before spending, then emits one shortfall row per talent, so
`Improved Charge`, `Deep Wounds`, `Impale`, `Piercing Howl`, `Improved Slam` and
`Improved Execute` no longer appear twice on the 46-point Arms link. A unit test
asserts uniqueness over three real Wowhead links and that the rows account for
exactly `requested - placed`.

`unplacedLine()` writes the sentence:

- `Improved Charge: placed 2 of 3 points, Forever has 2 ranks.`
- `Tactical Mastery: 3 points lost, not in Forever.`
- `Anger Management: placed 0 of 1 point, the rest does not fit the tree.`

`importReport()` is now a headline only — *"21 of 51 points placed. 6 talents
did not fit. 30 points left to spend."* — with no names and no truncation. "and
N more" is emitted by the dialog alone, and only when its 24-row cap actually
bit.

The dialog itself moved out of the 320 px summary column into a modal.
`web/src/ui/Modal.tsx` is the shell (fixed backdrop, centred panel, focus in on
open, Tab trapped, Escape and backdrop press to close) extracted from
`ShortcutsOverlay`, which now uses it too — one focus trap, not two. Test ids
are `<base>-backdrop` / `<base>-dialog` / `<base>-close`, so the existing
shortcuts tests are unchanged. CSS renamed `.shortcuts-backdrop`/`-dialog`/
`-head` → `.modal-*`.

## E4/E5 — one wording, from the build index

**`web/src/data/facts.json`** is new and generated: `{ talents: { total,
reviewed, queued }, racialTraits, spellEntries, spellTooltips }`, ~220 B, only
`origin: 'talents'` classes counted so the example classes in dev and e2e builds
cannot move the number a player reads. Never hard-code these counts again.

**`web/src/ui/trust.ts`** is the single place for the wording, per the brief:

- `SOURCE_LINE`, `RANKS_LINE`, `TWO_READINGS_LINE`, `ONE_READING_LINE`;
- `checkedLine({total, reviewed}, noun)` → *"57 of 469 talents have been checked
  by hand; the rest are as read."* / *"None of the 37 racial traits has been
  checked by hand yet; they are as read."* / *"All 4 talents have been checked
  by hand."*;
- `datasetTrustLines(records, noun)`, one implementation for the races page and
  the spellbook page (they were line-for-line identical and both claimed
  "Read from BlizzCon 2026 footage" whatever `source.kind` said — K-25);
- `playerNotes(notes)`, and the `INTERNAL` guard extended with the round-two
  vocabulary (`vision model`, `rank-0`, `extracted`, `anticipated`, `N
  readings`, `N% confidence`, `unreviewed`/`not yet reviewed`/`nothing here is
  reviewed`, `demo build YYYY-MM-DD`) plus the old `spellsModel.PIPELINE_WORDS`
  list, which is gone — one guard now.

Consequences: the landing paragraph, the footer and the class-page caveat all
print the counted sentence; the header tagline drops "and unreviewed" (and its
stray leading `-` became `·`); `readingLine` no longer appends a confidence
percentage; the `?` card's labels are *The version shown* / *A second
transcription*; the spellbook says *(two versions seen)*; and the class page
prints `RANKS_LINE` itself and passes `cls.notes` through `playerNotes`, because
`data/talents/*.json` is the pipeline's file and its notes are the pipeline's
prose ("Extracted … rank-0 tooltips only; ranks 2+ are anticipated"). The same
filter removes the duplicated second caveat on `#/races/<race>` and
`#/spells/<class>` (finding 16) — today it drops **every** note in those files,
which is correct: the only one that used to survive was a second copy of the
page's own caveat.

New `web/src/ui/trust.test.ts` (11 tests) pins all of it, including a table of
the exact strings the round-two sweep found and a table of the sentences that
must stay. A Playwright test walks six routes asserting none of them contains
"unreviewed", "vision model", "rank-0", "frame crops", "% confidence" or
"readings)".

## E6 — the Reworked diff is two lines

`diffLines(text)` in `web/src/ui/changesModel.ts` splits the existing
`compactDiff` ops: a `-` run belongs to the Classic line, a `+` run to the
Forever line, a `=` run to both. Nothing is recomputed and the raw sentences are
untouched. `web/src/ui/DiffLine.tsx` renders one labelled line — its own module,
not a helper inside `ChangesPage`, because the tooltip's nested card draws the
same two lines and `ChangesPage` is a lazy route the calculator must not pull
in. CSS in `diff.css` (`.classic-line`, `.classic-line-label`,
`.classic-line-classic` at 82 % opacity) and an inline label override in
`changes.css`.

Defiance now reads as two sentences instead of *"Increases ~~the~~ all threat
generated ~~by your attacks by 3%~~ ~~while~~ in Defensive ~~Stance.~~ stance
by an additional 5% …"*. Screenshot of `#/changes/warrior` (24 cards) taken and
read; Playwright asserts the Classic line carries no `.diff-add` and the Forever
line no `.diff-del`, on the page and on the nested card.

## E7 — markers and rings say the same thing

`changeMarker(status)` in `web/src/ui/highlightNew.ts`: `new` → `'new'`,
`text-changed`/`values-changed` → `'reworked'`, everything else → none. A talent
has exactly one status, so the blue star and the new amber diamond
(`.changed-flag`, test id `reworked-flag-<id>`) share the one top-right slot and
can never collide — the three-slot rule and its non-overlap test are intact, and
`tests/round3.spec.ts` repeats the bounding-box assertion for the diamond.

Ring colours in `cells.css` now match the marker each cell carries: blue
`#4ea3ff` for new, amber `#e8a33d` for a rewrite, violet for a move (no corner
marker — the tooltip's "Moved from row 2 to row 1" is the whole story), dimmed
for unchanged. The two rings that lived in `diff.css` moved here so one sheet
owns the vocabulary. The legend gained `★ = new in Forever` and `◆ = reworked in
Forever` (finding 10), and the toggle is now **Highlight changes**, which is what
it does — it was called "What's new" and rang every changed cell in one blue.

## E8 — build tooling

- **The stale-generated-file guard can fail now.** `vite.config.ts` ran
  `generate()` from `config()` *and* `buildStart()` in every mode, so vitest
  rewrote the committed files before `generated.test.ts` read them (K-2). The
  plugin is dev-only (`apply: (config, env) => env.command === 'serve' &&
  config.mode !== 'test' && !process.env.VITEST`) and runs once.
  `generated.test.ts` now generates into `mkdtempSync(tmpdir())` and compares
  byte for byte, including the *set* of `spellCrops/*.ts`. Verified by injecting
  `"className": "STALE-MARKER"`: three tests fail and the marker survives the run.
  `npm run gen` is the fix, and CI runs `npm run gen && git diff --exit-code --
  src/data`.
- **`npm run e2e` exits 0** on a green suite, twice in a row, 92 passed. The
  round-two exit 1 was the `build:e2e` `tsc -b` failure surfacing through
  Playwright's `webServer`; CI now runs `npm run typecheck` before the suite
  (K-30) so a type error is reported as a type error, and the deploy job no
  longer runs vitest a second time.
- **Atomic generator writes** (K-19): `writeIfChanged` in both generators writes
  `<path>.tmp-<pid>` and renames. `classic-diff.json` is 120 kB and tracked.
- **Classic-diff counting ignores unpublishable spell records.** `publishable()`
  in `gen-data-index.mjs` requires evidence (not `confidence <= 0`, and a crop,
  a frame, or a non-video source). `spellCounts` and `tabCounts` use it, so a
  fabricated name can no longer be counted as "new in Forever" — "new" means
  "not in our Classic list", which makes a misread name *guaranteed* a New chip
  (D-2). Package D has since dropped the five records, so the filter is a no-op
  today; it stays as the rule.
- **The five normalisation misses** (D-6): `classifierText()` is
  `normalizeText()` plus inner-hyphen folding (`off-hand` == `offhand`), a
  trailing plural (`resistances` == `resistance`) and the filler words
  `a/an/the/your/all/of`. Used for the classification only; the word diff still
  comes from the untouched sentences. `rogue/dual-wield-specialization` is now
  `values-changed` with `10% → 5%` instead of hiding a nerf behind "Reworked".
  Totals moved by exactly five: text-changed 127 → 124, values-changed 22 → 23,
  same 68 → 70.

## E9 — entry CSS

`talents.css` (1,102 lines) is gone, split three ways:

- `web/src/ui/shell.css` — `.panel`, `.serif`, `.btn`, `.skip-link`,
  `.app-shell`, the landing cards, the class crest, the continue card, the `?`
  trigger and the dialog shell. Imported by `index.css`, so it is what every
  route pays for.
- `web/src/ui/calculator.css` — the tree grid, cells, tooltip, control row,
  summary column, import, class switcher, level control, embed and pinned-card
  rules. Imported by `ClassPage`, together with `print.css`.
- the review-route rules moved into `web/src/ui/review.css`.

`ClassPage` is **lazy** in `App.tsx` like every other route, which is what puts
`calculator.css` (14.2 kB raw / 3.7 kB gzip), `tooltip.css`/`diff.css` and
`classic-diff.json` into route chunks instead of the entry. That last one is
also K-17's 60 kB: the entry chunk lost 41 % of its bytes as a side effect.
Tailwind is untouched — it is 9.7 kB raw of the entry sheet and removing
preflight would be a whole-app visual risk for ~2 kB.

Two e2e adjustments follow from the lazy class route: a `toBeVisible()` wait
before a non-retrying `count()` in `ui-round1a.spec.ts`, and the embed branch of
`App.tsx` needed its own `<Suspense>`.
