## 1. The summary column and the exports (idea 1)

`src/ui/BuildSummary.tsx` renders the spent talents grouped by tree, in row
order, each row a button that jumps to its cell (the same `jumpTo` the search
results use) and outlines it on hover. Empty state: "No points spent yet.
Click a talent to start."

The model and the text export are pure and unit tested in
`src/ui/summaryText.ts`:

- `summarizeBuild(cls, build)` - per tree points and talents, the `31/0/20`
  spread, points left, required level.
- `buildAsText(cls, build, link)` - the Discord block, deliberately plain text
  with no markdown so it survives a paste into a forum, a wiki or a code fence:

```
Warrior 17/0/0 (level 26) - WoW Forever
Arms (17): Improved Heroic Strike 3/3, Improved Rend 3/3, ...
34 points left.
https://.../#/warrior?v=1&t=303050013
```

Three buttons plus Import: **Copy link** (`data-testid="copy-link"`, moved here
from the header as the brief asks), **Copy build code** (the bare `t=` string,
which the import box accepts) and **Copy as text**. A clipboard refusal falls
back to a selectable textarea rather than failing silently.

Undo / Redo buttons sit below them, because the summary column is where a
player is looking after a mistake.

## 2. The wide-desktop layout (idea 5)

One CSS grid on the class page, `trees | summary`, in `talents.css`:

- `.class-layout` owns `--cell`, `--gap` and `--arrow-scale`. `--cell` steps
  44 -> 50 -> 56px at 1500px and 1800px of viewport, `--gap` 12 -> 13 -> 14.
  The tier gutter from round 1b reads the same two variables, so it scales with
  the grid for free.
- `.tree-columns` (not `.tree-row` - that class is already the `role="row"`
  element inside a grid) is `align-items: stretch`, so the three panels share
  one height instead of ending at three different y positions.
- `.app-shell` replaces the hard-coded `max-w-[1200px]` in `App.tsx` and grows
  to 1440 / 1560 / 1720px on the same steps.

**The two-column breakpoint is 1320px, not the brief's 1180px.** Round 1b's
tier gutter costs every tree 34px, so three trees plus a 320px summary need
about 1244px of content before something wraps. Below 1320 the summary sits
under the trees.

**`--arrow-scale` is a temporary bridge.** `Arrows.tsx` computes its geometry
from a constant 44 + 12 pitch and belongs to round 1b, so instead of editing it
the SVG is scaled by `(cell + gap) / 56` - exactly 1.125 and 1.25 at the two
steps, because the geometry is linear in the pitch. Delete the
`.tree-grid > svg.arrows { scale: ... }` rule the day `Arrows.tsx` reads
`--cell` itself; leaving both in place would double the scaling.

## 3. Class switcher (idea 2)

`src/ui/ClassSwitcher.tsx` in the class header: one chip per class from the
build-time `classes-index.json` (no class chunk is fetched), the current class
marked `aria-current="page"`, class-coloured initials until the nine
`classicon_*.jpg` files are fetched.

Every chip is a real `<a href="#/<class>">`, so it is keyboard reachable and
middle-clickable, and it carries no `t=` - an empty build, because talent ids
are per class. The brief's guard is satisfied by the cheaper of its two
options: the build you left is exactly one Back away, which the history policy
below guarantees.

## 4. Undo, redo, and one history entry per session (idea 7)

`src/ui/history.ts` is a pure reducer (`editReducer`) over
`{ key, past, present, future }`, capped at 50 snapshots and **keyed by the
route**: arriving at a different build (Back, a pasted link, an import) starts
a fresh stack instead of letting Ctrl+Z walk into a build the URL no longer
describes. `ClassPage` drives it with `useReducer`; `commit()` is the only
writer, so **Reset is undoable for free** - it is an ordinary commit.

`undoShortcut()` maps Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z and Ctrl+Y, and
`isTextEntry()` keeps the browser's own undo inside the search box and the
import textarea. Both are unit tested.

The hash still follows the stack with `replaceState`, **except for the first
edit of a session, which does one `pushState`**. So one Back leaves the edits
and a second leaves the page, instead of unwinding thirty clicks. The flag is a
ref keyed by the route (`pushedFor`), not reducer state.

For eight seconds after a Reset the button itself becomes
`Build reset - Undo` (`data-testid="reset-undo"`), so the recovery is visible
to someone who does not know Ctrl+Z.

## 5. Continue where you left off (idea 8)

`src/ui/storage.ts`: `wft.last = {classId, v, t, className, spread, savedAt}`,
every access wrapped in try/catch (a private window, blocked site data and a
full quota all throw), every read shape-checked, never thrown. `className` and
`spread` are denormalised so the landing page can render
"Continue: Warrior 31/0/20" without loading a class chunk.

**The URL always wins.** Storage is read only where the hash carries no build -
the landing page (a card with a "forget" link) and a bare `#/<class>` (one
line above the trees) - and it is always offered as a link, never applied. An
empty build is not written at all: writing one would wipe the entry the moment
a player opens a bare `#/<class>`, which is exactly where the card belongs.

## 6. Import (idea 9)

`src/url/import.ts`, pure, plus `src/ui/ImportDialog.tsx`. Three inputs, in the
brief's order: a link to this site, a bare build code, a Wowhead Classic link.
Nothing is applied until the player has pressed Check and read the report.

**Wowhead's format is confirmed, not assumed** - the brief listed it as the
risk that could kill the feature. Format:
`/classic/talent-calc/[embed/]<class>/<tab1>-<tab2>-<tab3>[/<talent order>]`,
one decimal digit per talent, **row-major within each tab**, trailing zeros
trimmed, trailing tabs omitted, empty tabs written as empty segments
(`0503--550340510553151`), tabs sometimes padded past the talent count, and a
Season of Discovery link appends `_<runes>` to the last tab. Confirmed against
`Lethay/TalentedClassic`'s decoder and exporter, `wowsims/classic`'s Wowhead
scraper (which sorts the DOM nodes by `row * 4 + col`), and twelve build
strings from Wowhead's own guides whose digit sums all match their labelled
spec and total 51. `classicIndex.test.ts` re-checks the row-major claim the
hard way: three real labelled builds (warrior 17/34/0, mage 31/0/20, rogue
15/31/5) decode to builds that satisfy Classic's own five-points-per-row rule,
which a wrong order would not. The old letter-encoded `wowhead.com/talent#...`
is detected and rejected with a sentence saying what to do instead.

The Classic order comes from `src/data/classic-index.json`, generated by the
new `web/scripts/gen-classic-index.mjs` from
`data/prior/classic-era/talents.json` (25 kB, 3.7 kB gzip, its own chunk
fetched only when someone actually pastes a Wowhead link).
`src/data/classicIndex.test.ts` regenerates and compares, so a stale commit
fails the unit suite - deliberately a separate generator from round 1b's diff
in `gen-data-index.mjs`, which needs the opposite direction of the same data.

**Mapping.** Classic talent -> Forever talent by normalised name within the
class, then the points are spent top-down through the ordinary `canAdd`
verdict, one at a time, in the order a player would have to click - never a
special case, so an imported build is always a build the rules accept and the
notice bar stays empty. A second pass exists because a row can become
affordable once the rows above it are filled. Everything that did not fit is
reported by name and reason:

> 16 of 51 points placed. Dropped: Tactical Mastery (not in Forever), Improved
> Battle Shout (not in Forever), Anger Management (does not fit the tree), ...
> 35 points left to spend.

That is the real Wowhead 17/34/0 Fury build. 41 of 52 Classic warrior names
still exist in Forever, but Arms and Fury were re-laid out, so a deep Classic
build loses most of its lower rows. The Protection tank build keeps 27 of 51.
Both numbers are pinned in `import.test.ts`: they are a fair measure of how far
Forever has moved, and they will change when the data is reviewed.

## 8. Verification

`cd web && npx vitest run && npm run build && npx playwright test` - green:
**237 unit tests in 18 files** (55 of them new) and **49 Playwright tests**
(15 new). Round 1b ran in parallel, so the two suites contend for port 4173;
if that happens again, a scratch config with `--port 4174` and
`reuseExistingServer: false` lets both run at once.

`web/tests/ui-round1a.spec.ts` covers the summary text export and the bare
code, the class switch (including that Back restores the build and that Enter
on a chip works), undo/redo from the keyboard and from the buttons, Reset being
undoable both ways, the one-entry-per-session history policy, all three import
paths plus two refusals, the continue card and its "forget", and the wide
layout at 1920 and 1500px (cell size, equal panel heights, the summary beside
the trees rather than under them).

Checked visually at 1500 and 1920px (`#/warrior` with an imported Wowhead
build, `#/paladin` with twelve points): 50px and 56px cells, the tier gutter
and the arrows scaling with them, the three panels level, and the trees plus
the summary as one centred block with no dead column. Screenshots are in the
session scratchpad, not committed.

Two bugs the screenshots and the suite caught, both worth knowing about:

- **Back did not restore the pristine build.** With `replaceState` the route
  props are identical before and after a Back from `#/paladin?t=...` to
  `#/paladin`, so the route key could not notice the navigation. `ClassPage`
  now listens for `popstate` and drops the stack there.
- **The trees column sized itself on the help sentence.** A `max-content`
  grid track took the one-line width of the interaction hint, which pushed the
  summary to the right edge and re-opened the dead space the layout was meant
  to close. `.class-help` caps it at 90ch.

One interaction with round 1b worth recording: shift-click-to-max commits one
point per render, so it produces five undo entries rather than one. Ctrl+Z
then walks back a point at a time. That is defensible (it is what the rules
engine actually did) but if it ever annoys, the fix is a `commit` variant that
coalesces while a `Repeat` is in flight.
